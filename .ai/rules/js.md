# Js

## Storefront copy, numbers and head tags each have one home
Interface copy lives only in `resources/js/lang/bn.ts`; Merchant-set text arrives as props. Display numbers go through `lib/bangla.ts` (Bangla digits, Indian grouping, `formatTaka`, `formatPhone`), and every numeric/phone input through `toLatinDigits`/`parseWholeNumber`. SEO tags are drawn twice under the same keys: `resources/views/app.blade.php` inside `<x-inertia::head>` (the no-SSR fallback, `data-inertia="key"`) and `components/storefront/seo-head.tsx` (`head-key="key"`, used when SSR answers and on client visits). Add a tag to both or a crawler sees it only half the time. Colours are tokens in `resources/css/app.css`; components write no hex values.

## Every view of the Cart goes through useCart()
A bulk Cart's Contents (ADR-0029, ADR-0038) are `lib/cart.ts` (kept per Cart id in `lib/contents.ts`, pure helpers Vitest-tested in `cart.test.ts`) read only through `useCart(cartId)` in `lib/use-cart.ts`, which prices it with `lib/pricing.ts` from the shared `pricing` prop (`StorefrontShell::pricing()`: every published Product sold পাইকারি, its Tiers + isAvailable, and the Delivery Bands). Never read localStorage or keep a second quantity in a component. `useSyncExternalStore` gives SSR an empty Cart, so nothing that touches `window` may run during render. Writes drop lines for Products not Available/not sent (`onlyOrderable`), so an unavailable tea never comes back unasked. A Bulk Order row is addressed as `#tea-{id}` via `rowAnchor`/`rowFromAnchor`.

## Storefront Moments go through lib/tracking.ts and useMoments()
The storefront reports Visit, Product Viewed, Added to Cart and Checkout Started only through `lib/tracking.ts` (`reportMoment()` calls `window[tracking.moments][moment](id, selection)` from `TrackingSnippet::forStorefront()` and `sendBeacon`s the same id). Pages use `useMoments()`; never call `fbq` or post to the beacon from a component. Visit is fired from `reportVisits()` on Inertia's `navigate` event, skipping a same-URL navigate (partial reload). The base code fires no bare PageView on the storefront, so a second copy would be undeduplicated. Added to Cart is raised in `changeBulkContents()` (behind `useCart().set` and `useAdding()`) when a Product goes from 0 to some, once per Product per Cart's Contents: `bongotea.cart-moments.{cartId}` holds a Contents id (a new one when the Contents were empty) and the Products reported, and the deduplication id is `{contents}-{productId}`. A Moment's selection is priced with `priceCart` over just what was named, matching `Selection::forProducts()`. The shared `tracking.beacon` is null when the store reports nowhere and counts no Visits; skip the beacon then.

## The retail Cart is a second store, read only through useRetailCart()
A retail Cart's Contents (ADR-0034) are `lib/retail-cart.ts` (`{packId: count}`, kept per Cart id in `lib/contents.ts`, Vitest-tested in `retail-cart.test.ts`) read only through `useRetailCart(cartId)`, which prices it with `lib/retail-pricing.ts` from the shared `retailPricing` prop (`StorefrontShell::retailPricing()`: every Pack ticked খুচরা of every published Product sold খুচরা, with `isOrderable`, plus the retail Delivery Charge and threshold). It never reads or writes the bulk Cart, and nothing on the bulk side reads it. Unlike the bulk Cart, Packs that can no longer be ordered stay visible in the basket (`unorderable`, flagged and out of every figure) until the next write drops them through `onlyOrderablePacks`. A Product is open to retail exactly when `packsOf(productId)` is non-empty — the server sends only Packs ticked খুচরা of Products sold খুচরা, so no flag is sent for it. Bulk is the card's `isSoldBulk` (ADR-0036): `ProductCard` is a union, a `RetailOnlyProductCard` has `mrp: null` and no Tiers, and the bulk Blocks take `BulkProductCard` only. Pack names are drawn only through `packName()` in `components/cart/figures.ts`.

## স্টক শেষ is computed from the Carts' freeGrams, never stored
Free to Sell reaches the storefront only as `freeGrams` (null = uncounted, never স্টক শেষ) on `pricing.products` and `retailPricing.packs`, loaded by `CommittedStock::withFreeToSell()` inside `Catalogue::products()` — never a per-card query. স্টক শেষ is worked out in the page: bulk `isBulkSoldOut` (< 1 kg free), Pack `isPackSoldOut` (< its grams), a whole Product via `useIsSoldOut()`. Steppers stop at `mostKilograms()`/`cappedCount()` (lower of Order Limit and Free to Sell) but never stop coming down. A line beyond what is free is flagged (`short`/`isShort`) and holds up Checkout; the server still refuses it. Never touches Available/isOrderable.
